# kb v1.5.0

v1.5.0 is a minor release carrying five changes. The board card is re-cut end
to end - the title wraps, the description is markdown, the meta row speaks one
grammar, and labels take rows of their own - and the priority scale collapses
from four values to three, which migrates the store to schema v10 and changes
what `--prio` accepts. Two rendering defects reported against v1.4.4 are fixed:
the half-block pill end caps are gone, and a wide mark no longer clips the text
beside it. The AI connection test says what failed instead of answering every
failure with one sentence.

The bump is minor and not patch for two reasons, and both are behavioral rather
than cosmetic. The database migrates: a stored priority outside 1-3 is rewritten
to 3 the first time a v1.5.0 binary opens the board. And the CLI surface changed:
`--prio` takes `high|medium|low`, with `1|2|3` accepted as aliases, and a value
above 3 is refused on write where it used to be stored. No command was added or
removed, the `kb serve` HTTP API and the MCP tool surface keep their shapes, the
markdown and JSON wires are unchanged, and no dependency was added.

## Pills are flat spans of color

A label pill used to be a colored word between two half-block end caps. The cap
was the only piece of the pill language that depended on font geometry rather
than on color cells, and it failed in both directions: a seam on a filled pill
wherever the font did not draw the half block flush to the cell edge, and two
colored bars by construction on an inactive pill, which has no fill for a cap to
fuse into. v1.4.4 gave the caps the pill's own hue, which fixed the second
symptom by making the bars match; it did not fix the first.

Every pill form is now a flat span. One cell of the pill's own ground at each
end replaces the cap that used to sit there:

```
before   ▐#backend▌   a half-block cap, the tag, a half-block cap
after     #backend    a pad cell, the tag, a pad cell
```

Nothing moves. Each cap was one cell and each pad is one cell, so the padded
form still costs the mark plus the text plus two columns in every state, and the
compact flat form still costs the mark plus the text with no padding at all.
Mouse hit regions were already measured from the rendered run rather than from a
constant, so the padding cells were inside the region before and stay there.

The scoped pill - every `project::` and `type::` pill on the board - keeps its
two tones. The junction glyph is gone and nothing replaces it: the leading pad
and the key run are one Surface span, the body and the trailing pad are one fill
span, and the tones meet at a cell edge.

```
 type:feature
```

The keyboard focus cue moved with the caps. Thickening both caps to full blocks
is not available when there are no caps, and the pill has no depth tier to raise
and no cell to spend, so focus bolds the body run. Hover keeps its underline and
the two compose, which the filter bar needs because it can carry both at once.

`Glyphs.CapL` and `Glyphs.CapR` stay in the vocabulary. They are not dead - the
progress meter still caps its bar with them - and their doc comments now name
the meter rather than the pill.

## A wide mark ends its own styled run

The v1.4.4 effort square arrived with the adjacency rule that a wide mark owns
the column after it, so nothing would be written on top of the glyph. The rule
was not enough, and the report that followed showed why.

A terminal shapes one styled run as one text run. A color pictograph is drawn by
font machinery whose advance is wider than the two columns the cell grid gives
it, so every glyph after it *inside the same run* is pushed right by the excess,
and the next run - placed by the cell grid rather than by the pen - is painted
over the tail of the last glyph. The card meta row emitted the effort square, the
owned column and the letter as one run, and the letter came out cut down the
middle. The same shift explains a title reported as rendering `dogfooc`: a title
carrying a leading emoji is nudged as a whole, and it only shows once the title
runs long enough to reach the padding run that repaints over its last letter.

`widget.MarkRun` renders the mark and the column it owns as a run of their own
and starts a fresh run for the text beside them. The overhang stays on the column
the adjacency rule bought for it, and the text lands on the cells the grid gave
it. The mark run takes the ground as its foreground, because a two-cell mark is a
color pictograph and has no foreground to lose, and the column beside it has no
ink. A one-cell mark that does carry a real foreground, an empty mark, and a run
the caller already truncated past its own mark all keep the single run.

Nothing moves here either. The same cells are emitted in the same order; only the
SGR boundary between them moves.

The scoped label was reported in the same issue and was found correct at every
form. A `#scope:terminal` tag has a single colon, so it is a plain tag rather
than a scoped one, and it takes the tag mark. That half of the report is now
pinned by a test so nobody has to re-derive it.

## The AI connection test names what failed

The connection test in the settings overlay was sound - endpoint, auth header,
request shape and timeout were all correct - but its failure output never said
what failed. A rejected API key, an unresolvable host, a wrong model name, a TLS
failure and a timeout all rendered the same row:

```
upstream request failed
```

Two layers were destroying the cause. The backend library reduces every failure
to one string with no wrap and nothing to unwrap, deliberately, so that a caller
cannot use a configured endpoint as a reachability oracle. kb then reduced the
remainder again. The worst casualty was kb's own SSRF guard, whose message is the
single most actionable thing the test can say and which no caller could ever see:
that is exactly the failure someone pointing kb at Ollama or LM Studio hits, and
the overlay answered it with "upstream request failed".

The probe now records its own single round trip at the transport kb owns, so the
upstream status code and the dial error survive that reduction without parsing
anyone's message text. The test reports the failure as itself:

| failure | now reads |
| --- | --- |
| bad key | `the AI endpoint rejected the API key (HTTP 401) - check the key` |
| wrong model or path | `the AI endpoint returned HTTP 404 - check the base URL and the model name` |
| local model server | `AI endpoint resolves to a private address (set KB_AI_ALLOW_PRIVATE=1 for local model servers)` |
| host does not resolve | `the AI base URL host does not resolve - check the base URL` |
| host unreachable | `could not connect to the AI endpoint - check the base URL and that the server is running` |
| TLS failure | `the AI endpoint's TLS handshake failed - check the scheme and the certificate` |
| timeout | `the AI endpoint did not answer before the test timed out` |
| blank model | `AI model not configured - fill in the model field` |

A blank model is caught before the request, because the backend rejects it with
neither a sentinel nor a round trip, which would otherwise leave the probe unable
to tell it from an unreachable host.

The HTTP surface keeps its opacity. `kb serve` redacts by status code and
collapses every network and upstream outcome to the same one sentence it always
returned, logging the detail; the cause reaches only the local settings overlay.
The one new message carrying a pass-through code describes the caller's own
settings rather than the network.

A status row cut at the overlay's 160-rune cap now ends in an ellipsis, so a
truncated cause is not read as a complete one.

## The card anatomy is re-cut

The board card's rows are re-cut end to end, and the meta row becomes one
grammar: a single ASCII character on a colored fill, plus short values.

```
🧭 Prepare parity dogfood                    ⛔ #12
Ships the card anatomy at card scale
 1  3d  !5d  M
 #backend   type:feature
```

The priority and effort chips and the overdue due chip are each a padded flat
span - a digit or a letter on its own fill - and the label pills below them take
the same form. Age and a deadline still ahead are unfilled muted text.

**The title wraps.** Two rows at normal density, one compact, with the ellipsis
on the last allotted row only. The trailer - the blocked alarm and the sequence
number - holds the right end of the first row and is never truncated; it narrows
that row alone, and the rows under it take the full content width, which is where
a wrapped title gets the space a one-line title never had.

**The description is markdown.** One row, rising to five as the frame gets
taller: one below 45 rows, two at 45, and one more per ten rows after that up to
five. The allotment is a frame property and never a content one, so a short
description leaves its rows blank and the rows under it do not move up, and a
long description never costs a card off the bottom of a column. The grammar is
headings, bullets, ordered items, fenced code, and inline bold, italic, code and
links. `internal/tui/mdparity` is new and holds the recognizers both description
surfaces read - the card detail pane still hands reduced source to glamour, the
card takes the runs and wraps them itself. Two consumers, one grammar, and it is
the frozen grammar rather than a second one.

**Priority is the digit on its hue.** Three cells padded and one flat. Digits and
not H/M/L because the effort marker on the same row is already a letter on a fill
and renders an M of its own; two letter-on-fill Ms a few cells apart would be one
grammar saying two unrelated things.

**Effort is the letter on its hue** - S blue, M yellow, L orange - with the same
anatomy. The three emoji squares v1.4.4 introduced retire after one release. A
pictograph proved font-dependent whatever its pinned width, and the value it
carried was one of three, so a substituted glyph lost information rather than
merely looking wrong. A value off the S/M/L scale still falls back to the diamond
and the column the adjacency rule gives it.

**Due splits in two.** A deadline still ahead is plain muted text - `today`,
`tomorrow`, `in 3d` - because a card that is merely scheduled is not an alarm and
does not earn a fill on a row with three other things to say. A deadline behind
is the mark and the bare elapsed count on the danger fill:

```
 !5d
```

The mark and not the color carries the fact: `!` says the deadline has passed on
a terminal with no hue at all, and the three readings stay distinguishable as
text. The word "overdue" and two pill padding cells used to spend nine columns
saying what the mark says in one.

**Age is the bare count** - `3d`, `6h`, `new`, `shipped`. The column already says
which clock the number came from.

**Labels take rows of their own** below the meta line, pill form unchanged, with
a fixed one-cell gutter and a greedy wrap onto a second row. A fixed gutter is
what "equally spaced" means on a cell grid: every gap is the same cell whatever
the row holds.

**Blocked moved to the title row.** `⛔` U+26D4 sits beside the sequence number
in the trailer, owning the column after it. Being blocked is a fact about the
card rather than about its schedule, and it is the one thing a substituted glyph
cannot garble - tofu beside a sequence number still says this card is flagged,
where a substituted effort square lost which of three values it carried. It is
the one pictograph left in the vocabulary.

The row grid stays a pure function of density and frame height, which is what
lets a column reserve its scroll affordance and its `+N more` cue before its
cards are rendered. Inside it, the title and the description share one fixed
block: a title that fits one row hands its spare row to the description rather
than spending it on blank surface, and the meta row sits at the same offset
either way. `Metrics.CardRows` is the single place that grid is resolved, so the
panel that reserves a column's height and the widget that draws the card cannot
disagree about it.

## The priority scale is three values

The scale is 1 high, 2 medium, 3 low. The card anatomy collapsed the render seam
and left the data behind it; this migrates the store and takes the tolerance back
out.

**The stored representation is unchanged.** `tasks.prio` has always been
`INTEGER NOT NULL DEFAULT 3`. The card renders the digit, the markdown and JSON
wires carry the number, and the HTTP API's `prio` field is typed as an integer
for a web client that is frozen. Names in the column would rewrite all of those
to gain nothing the names already give at the surface.

**The CLI takes names, and the digits alias them.** `--prio high|medium|low`,
with `1`, `2` and `3` accepted, and `med` for medium. The digits are what the
card prints and what every existing script types; refusing them would break
callers to teach a vocabulary the card does not itself display. A value outside
the scale is now an error naming the scale:

```
invalid prio "4" (want high, medium, or low; 1, 2, and 3 are accepted)
```

**The migration is schema v10** - one statement appended to the existing
migration slice, applied under `BEGIN IMMEDIATE` and recorded in the version
ledger. No new machinery:

```sql
UPDATE tasks SET prio = 3 WHERE prio < 1 OR prio > 3;
```

P1 to high, P2 to medium, P3 to low, P4 to low - which is what a P4 always meant.
The predicate also catches values the old scale never named, because the column
has no `CHECK` constraint and a legacy writer could have put anything there. No
`CHECK` is added now either: SQLite needs a full table rebuild for one, and the
write paths are the enforcement point.

It is idempotent by construction. The predicate is false for every row the
statement has already rewritten, so a second execution reports zero rows
affected, and the version ledger means it runs once regardless.

`migrate` runs inside `store.Open` before any caller can read a task, and WAL is
enabled only after it returns. A v1.5.0 binary on an older database therefore
migrates before the TUI sees a card, and there is no window in which a stored 4
reaches the render seam. That is what let the render-side tolerance go.

**The two write behaviors are deliberately different.** A path taking a whole
task normalizes onto low, because a zero-valued priority on a struct literal
means "unset" and unset has always defaulted to 3. A path naming the field
explicitly rejects an out-of-scale value: the caller asked for something
specific, and silently storing something else is worse than an error.

The `Prio4` palette slot is deleted and the color audit tables are re-pinned
against the three-hue ramp. Its index was uncontested and it was in no alias
group, so no other slot moved.

## Two things left alone on purpose

**The markdown reader still tolerates `!4`.** The wire is frozen and boards on
disk carry the token, so narrowing the pattern would demote a `!4` to a title
word rather than reading it as the low priority it always meant. The reader
accepts it and normalizes; the writer normalizes before serializing, so kb never
emits a token it only tolerates. A `!4` consequently cannot round-trip - it reads
as low, and low is the omitted default - which is the correct behavior and is
pinned by a test of its own.

**No priority sort or filter was added.** This is a finding rather than an
omission: there is none anywhere in the repo. Board order is status rank then
position, the store's task filter carries status, search text and tags, and the
TUI filter predicate matches text and tags only. Both surfaces are correct on a
three-value scale because neither reads priority at all. Adding one is a feature
and not part of this migration.

## Upgrade from v1.4.4

**The store migrates itself.** The first time a v1.5.0 binary opens the board,
schema v10 applies inside `store.Open`, before anything can read a task. Nothing
needs to be run by hand and nothing needs to be reconfigured. The migration is
idempotent - it is recorded in the version ledger so it runs once, and the
statement itself rewrites nothing on a second execution - so an interrupted open
and a reopen are both safe.

**A stored priority of 4 or higher becomes low.** So does anything below 1. This
is a write to your database and it is not reversed by downgrading. Low is what a
P4 has always meant and what this release's card anatomy already renders it as,
but it is now the value on disk. Back up the board first if you want the old
integers retained anywhere.

Downgrading afterwards works. The v10 migration is a data statement and adds no
DDL, so the table shape is identical, and an older binary skips a version ledger
ahead of its own migration list rather than failing on it. The migrated data is
inside the range every older version accepts.

**The card layout changed substantially.** Cards are taller: at normal density a
card is a wrapping two-row title, one to five description rows, the meta row and
up to two label rows, against the flatter card of v1.4.4. Descriptions now render
as markdown at card scale rather than as a plain snippet. The blocked marker
moved off the meta row and onto the title row's trailer beside the sequence
number. Fewer cards fit a column of a given height, and the number that fits
changes with the frame height rather than being fixed. Compact density is
unchanged at two rows and is the way back to the old card count.

Existing tasks, comments, links, tombstones, settings, encrypted credentials and
import provenance stay in the same data directory. Keep `kb.db`, `kb.db-wal`,
`kb.db-shm` and `secret` together when backing up or moving a board.

Scripted use is otherwise unaffected. The markdown wire, the JSON wire and every
export are unchanged, and `--prio 1|2|3` keeps working exactly as before. The one
break is `--prio 4` and above, which is now refused where it used to be accepted.

## Install and verify

With Go 1.25.8 or newer:

```sh
go install github.com/RandomCodeSpace/kb@v1.5.0
kb version
```

The release contains five CGO-free binaries:

- Linux amd64 and arm64
- macOS amd64 and arm64
- Windows amd64

Download the matching binary and `SHA256SUMS` from the release, then verify it
before installation:

```sh
grep ' kb-linux-amd64$' SHA256SUMS | sha256sum -c -
```

Substitute the downloaded asset name. On macOS, pipe the matching manifest
line to `shasum -a 256 -c -`. On Windows, compare
`Get-FileHash -Algorithm SHA256` with the matching manifest line.

Every attached binary is built from the annotated v1.5.0 tag with `-trimpath`
and stripped debug data. Embedded Go metadata records the module, version,
source revision, target OS and architecture, and an unmodified source tree.
