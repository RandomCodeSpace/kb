# kb v1.4.2

v1.4.2 is a patch release carrying a single fix to the TUI's markdown
renderer. Card descriptions and comments no longer render stray backslashes
in front of ordinary punctuation, so pasted configuration-shaped text such as
`key = value` or `time: 5m` arrives on screen as it was written. No command
was added or removed, no flag changed, the schema, the `kb serve` HTTP API,
and the MCP tool surface are untouched, and no dependency was added.

## Escapes no longer leak into rendered text

The card renderer pre-processes source text before Glamour draws it, and it
neutralized every ASCII punctuation and symbol rune with a backslash. That
assumed Glamour would strip the backslashes back out again. It does not:
Glamour bypasses goldmark's unescaping and instead runs a fixed replacer over
eighteen escape pairs, passing every other backslash straight to the terminal
as text.

Fourteen characters were therefore escaped and never unescaped, and they
leaked in ordinary prose rather than only in the indented case the report
named:

```
source                        rendered before        rendered now
key = value                   key \= value           key = value
a, b: c = d; e? f 50%         a\, b\: c \= d\; ...   a, b: c = d; e? f 50%
tea & coffee                  tea \& coffee          tea & coffee
~~strike~~                    \~\~strike\~\~         ~~strike~~
<b>html</b>                   <b>html<\/b>           <b>html</b>
```

The escape set is now bounded to what Glamour's replacer actually strips,
intersected with what is syntactic under the frozen parity grammar: the
inline delimiters, the leaf-block markers a line can begin with, and the
backslash itself. The parenthesis stays because `1)` is an ordered-list
delimiter; the period stays because it is the ordinal delimiter and because
linkification needs it.

Three characters are syntactic but sit outside that replacer, so a backslash
on them was precisely the bug. They travel as HTML character references
instead, which Glamour resolves back:

- `~`, which opens a tilde fence and delimits strikethrough.
- `&`, which has to follow, so a character reference the author typed stays
  their text instead of becoming the character it names.
- a leading `:`, which definition lists would otherwise pull into a
  description of the line above.

## What a 4-space-indented line means

The loudest report was a line indented four spaces, which Glamour read as an
indented code block, skipped inline parsing for, and printed every escape on
verbatim. That indent was the amplifier, not the cause, and the release
settles what it means rather than working around it.

Under the frozen web renderer's grammar, indentation carries no meaning. That
renderer matched headings, ordinals and bullets at column zero only, had no
indented-code concept at all, and emitted each line into a block that
collapsed the leading whitespace away. The TUI now matches it: a block is
classified on the raw line, so an indented `- x` is prose exactly as it was
on the web, and the indent is dropped before the line is emitted.

Dropping it closes the last context where Glamour skipped inline parsing, so
no injected escape can survive as text anywhere. Fenced code is untouched and
still renders verbatim.

## Upgrade from v1.4.1

No database migration is required and nothing needs to be reconfigured.
Existing tasks, comments, links, tombstones, settings, encrypted credentials,
and import provenance remain in the same data directory. Keep `kb.db`,
`kb.db-wal`, `kb.db-shm`, and `secret` together when backing up or moving a
board.

Nothing changes for scripted use. Stored text was never altered - the escapes
were injected on the way to the screen and never written to the database - so
no card needs repairing and no export changes. The only visible difference is
in the TUI, where card descriptions and comments that contain punctuation now
render without the stray backslashes.

## Install and verify

With Go 1.25.8 or newer:

```sh
go install github.com/RandomCodeSpace/kb@v1.4.2
kb version
```

The release contains five CGO-free binaries:

- Linux amd64 and arm64
- macOS amd64 and arm64
- Windows amd64

Download the matching binary and `SHA256SUMS` from the release, then verify it
before installation:

```sh
grep ' kb-linux-amd64$' SHA256SUMS | sha256sum -c -
```

Substitute the downloaded asset name. On macOS, pipe the matching manifest
line to `shasum -a 256 -c -`. On Windows, compare
`Get-FileHash -Algorithm SHA256` with the matching manifest line.

Every attached binary is built from the annotated v1.4.2 tag with `-trimpath`
and stripped debug data. Embedded Go metadata records the module, version,
source revision, target OS and architecture, and an unmodified source tree.
