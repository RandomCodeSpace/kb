# kb v1.4.3

v1.4.3 is a patch release carrying a single change to the TUI's card detail
overlay. A `kb://task/<seq>` reference written in a card description or a
comment now renders as a link and opens that card when clicked. No command was
added or removed, no flag changed, the schema, the `kb serve` HTTP API, and the
MCP tool surface are untouched, and no dependency was added. Stored text is
unchanged: this is rendering and navigation only.

## References open the card they name

Cards already referred to each other in prose. Writing `kb://task/111` in a
description or a comment recorded the intent, but reading it meant leaving the
overlay, finding card 111 on the board, and opening it by hand.

The reference is now a link. The inline matcher recognizes kb's own scheme the
way it already recognized `http` and `https`, as an autolink, so escaping never
touches the reference and it renders in the same link color the renderer gives
any other link. Clicking it opens that card's detail, taking the same path a
click on the board card takes.

Three cases stay literal text, because they are not references:

```
kb://task/111                 link
see kb://task/111 here        link
seekb://task/111              text - glued to a preceding word
kb://task/                    text - no sequence number
https://x/kb://task/111       text - inside an http URL
```

A card the current filter hides still opens. The reference is an explicit
request for that card, not a search within what is on screen.

## Unknown references report, they do not fail

A sequence number no card on the board carries is a notice in the pane -
`no card #N on this board` - not an error block and not a silent dismissal.
The overlay stays where it was.

## Hover and activation

The reference already wears the link color and the renderer's underline, so
hover does not re-hue the one cue that says it is a link. It raises the run's
ground a single depth tier instead, and a press keeps the standard pressed
feedback. Both treatments cost zero cells, so a hovered reference occupies
exactly the columns the resting one does and nothing on the row shifts.

Hit regions are anchored by scanning the rendered body rows and registered
through the pane's existing pointer viewport, so they follow the scroll offset
and clip at the window edge like every other region in a scrolled pane.

## Pointer only, deliberately

Activation is by pointer. The detail body is a scroll viewport with no keyboard
cursor, and a key that acts on whatever the pointer happens to rest over is
forbidden by the interaction rules the overlay follows. A keyboard path would
mean inventing a link cursor and a mode to drive it - a new interaction model
rather than a use of the existing one - so it is not in this release.

## Upgrade from v1.4.2

No database migration is required and nothing needs to be reconfigured.
Existing tasks, comments, links, tombstones, settings, encrypted credentials,
and import provenance remain in the same data directory. Keep `kb.db`,
`kb.db-wal`, `kb.db-shm`, and `secret` together when backing up or moving a
board.

Nothing changes for scripted use. The wire format, the stored text, and every
export are identical to v1.4.2; a `kb://task/<seq>` reference is stored as the
characters the author typed and always was. The only visible difference is in
the TUI, where those characters are now clickable.

## Install and verify

With Go 1.25.8 or newer:

```sh
go install github.com/RandomCodeSpace/kb@v1.4.3
kb version
```

The release contains five CGO-free binaries:

- Linux amd64 and arm64
- macOS amd64 and arm64
- Windows amd64

Download the matching binary and `SHA256SUMS` from the release, then verify it
before installation:

```sh
grep ' kb-linux-amd64$' SHA256SUMS | sha256sum -c -
```

Substitute the downloaded asset name. On macOS, pipe the matching manifest
line to `shasum -a 256 -c -`. On Windows, compare
`Get-FileHash -Algorithm SHA256` with the matching manifest line.

Every attached binary is built from the annotated v1.4.3 tag with `-trimpath`
and stripped debug data. Embedded Go metadata records the module, version,
source revision, target OS and architecture, and an unmodified source tree.
