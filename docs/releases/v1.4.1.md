# kb v1.4.1

v1.4.1 is a patch release for the TUI. It finishes the label pill that v1.4.0
shipped on board cards and carries it to the two surfaces that were still
rendering labels as plain text, then corrects the color of a pill that is not
selected. No command was added or removed, no flag changed, the schema, the
`kb serve` HTTP API, and the MCP tool surface are untouched, and no dependency
was added.

## Label pills everywhere labels appear

The section 3.6 pill was the board card's alone. The card-detail meta row joined
its tags into one flat string and the filter bar still carried v1.0.1's
`[+ tag]` / `[x tag]` markers. Both surfaces now compose the same `widget.Chip`
the cards do, rather than a second implementation of it.

```
card detail   before   labels      [type::feature]  [backend]
              after    labels      |type:feature|  |#backend|

filter bar    before   [+ backend] | [+ type::feature]
              after    |+ #backend| | |+ type:feature|
```

- **Wrapping** - card-detail pills wrap whole to the next row when the overlay
  is narrow, and the continuation row repeats the field gutter so the value
  column stays one straight edge. A pill is the smallest unit the row breaks on;
  one split across two rows would read as two pills with one cap each.
- **Inactive pills** - an unselected filter pill drops its fill to the surface
  tier while keeping the label wheel's hue as its body text, so it can still be
  matched by eye to the pill on the card it filters for. A selected pill wears
  the hue as a full fill. The scoped two-tone split survives the withdrawal: the
  key run sits one step under the body.
- **Toggle marker** - the `+` and `x` marks moved inside the caps rather than
  being dropped. At the flat fidelity floor there is no color at all, so the
  mark is the entire toggle affordance there. Both marks are two cells wide,
  which is what holds a pill's width fixed across the toggle.
- **Keyboard focus** - focus thickens both end caps instead of wrapping the
  label in `>` and `<`. The old brackets cost two cells, so moving the cursor
  along the filter row reflowed everything behind it. Focus now costs zero cells
  and borrows the block a selected card's rail already spends.
- **Pointer** - filter pills are hoverable through the hit regions they already
  carried, underlining the body run. Every region is measured from the width of
  the rendered pill rather than from the text that went into it. Card-detail
  pills are not hoverable; a field row is not activatable.

Toggle, focus, and hover are orthogonal, and none of them moves a cell: all
eight combinations are asserted against each other and against the board pill's
width.

## Contrast

Inactive pill text is now audited by a shipped test rather than by eye. Every
label-wheel hue clears the WCAG AA 4.5:1 floor as body text on the surface fill
in both the truecolor and the 256-color profile, the worst cases being 4.97:1
truecolor and 5.19:1 after quantization. The test also asserts that no two wheel
slots collapse onto the same 256-color index, so a quantized terminal cannot
merge two labels into one color.

The same audit caught a miss from earlier in this line: the scoped key run,
which carries the toggle marker a user must read before acting, measured 3.67:1
truecolor and 3.75:1 quantized - under the floor. It has been raised one step
and now measures 6.79:1 and 7.17:1.

## Upgrade from v1.4.0

No database migration is required and nothing needs to be reconfigured. Existing
tasks, comments, links, tombstones, settings, encrypted credentials, and import
provenance remain in the same data directory. Keep `kb.db`, `kb.db-wal`,
`kb.db-shm`, and `secret` together when backing up or moving a board.

Nothing changes for scripted use. The only visible change is in the TUI, where
labels in the card detail and the filter bar are drawn as pills; the filter's
selected set, its keys, and its behavior are unchanged.

## Install and verify

With Go 1.25.8 or newer:

```sh
go install github.com/RandomCodeSpace/kb@v1.4.1
kb version
```

The release contains five CGO-free binaries:

- Linux amd64 and arm64
- macOS amd64 and arm64
- Windows amd64

Download the matching binary and `SHA256SUMS` from the release, then verify it
before installation:

```sh
grep ' kb-linux-amd64$' SHA256SUMS | sha256sum -c -
```

Substitute the downloaded asset name. On macOS, pipe the matching manifest
line to `shasum -a 256 -c -`. On Windows, compare
`Get-FileHash -Algorithm SHA256` with the matching manifest line.

Every attached binary is built from the annotated v1.4.1 tag with `-trimpath`
and stripped debug data. Embedded Go metadata records the module, version,
source revision, target OS and architecture, and an unmodified source tree.
