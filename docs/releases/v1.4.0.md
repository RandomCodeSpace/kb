# kb v1.4.0

v1.4.0 is a craft release for the TUI. Nothing about the board's model changes -
no new verbs, no schema change, no wire change, no flag added or removed - and
every screen looks and feels different. Gradients replace flat rules, a branded
spinner replaces the stock one, input timing was tuned rather than left to the
terminal, the mouse gained hover feedback, `ctrl+k` opens a command palette, and
every empty, loading, and error state is now a designed screen instead of a blank
one. The CLI, `kb serve`, `kb mcp`, and the stored database are untouched.

The whole layer is governed by section 10 of the Strata design spec, drafted and
locked before any of it was built.

## Look

- **Gradient ramps** - column rules, section titles, the scroll rail, and meters
  render as 24-step ramps rather than one flat hue. Truecolor terminals get the
  ramp; anything less flattens each ramp to its lead color automatically, with no
  second design and no branching in the views.
- **Section titles** - overlay and dialog titles follow the surface's mode. A
  destructive dialog's title ramp turns danger-hued once the prompt is armed,
  which is the only header recolor in the TUI - a pending destructive action
  leaves the frame alone until you arm it.
- **Micro-typography** - buttons underline the one rune that already drives them,
  so the hotkey is visible without a second color. Priority chips, card
  references, tag pills, and due markers all render from a single glyph
  vocabulary, and the hint separator is now one token everywhere instead of three
  spellings of the same bar.
- **Brand mark** - kb draws its name in half-block letterforms on launch, with a
  staggered reveal, and the top bar carries a three-column accent run whose hue is
  derived from the active project. Two projects never wear the same bar.
- **Scroll rail** - columns show a proportional rail rather than a text
  indicator, and the rail's active state finally lingers instead of vanishing
  between keystrokes.

## Motion

- **Branded spinner engine** - one spinner engine, one spinner on screen at a
  time, with z-order handoff when a second surface wants it. Long-running work in
  the editor, the ADR split, and the forge import is branded; short work is not.
- **Ship celebration** - moving a task into `DONE` pulses that column's meta row
  twice over 600ms. It is suppressed on lesser terminals, and a write landing
  mid-pulse takes the motion back rather than talking over it.
- **Determinism** - every animation is seeded at its target value on first paint
  and every tick chain terminates on its own, so a settled frame is identical
  whether or not anything animated on the way there. Nothing about kb's output is
  now time-dependent once it settles.

## Feel

- **Input coalescing** - a burst of scroll notches or repeated keys is summed and
  handled once instead of re-rendering per event, so holding a key no longer
  outruns the board.
- **Destructive-prompt grace** - a destructive button ignores input for a grace
  period after the prompt appears, so a keystroke already in flight cannot
  confirm a delete you have not read. The dismissal keys are exempt: `esc` always
  works immediately.
- **Footer notices last 5 seconds** - a move or action notice now clears itself
  on a 5s timer as well as on the next keypress. This deliberately changes
  behavior frozen since v1.0.1, where a notice sat in the footer until something
  else displaced it.
- **Press feedback** - a pressed control now renders as a reverse-video
  attribute. The `!` and `>` glyphs that marked a pressed button in the editor,
  settings, and import panes are gone.

## Mouse

- **Hover** - cards, column bands, overlay rows, buttons, and label pills respond
  to the pointer. Hover treatments cost no cells, so nothing reflows as the
  pointer moves.
- **Mouse mode** - overlay choice surfaces run a real mouse mode: click to
  choose, click the backdrop to dismiss. The board itself stays keyboard-anchored
  on purpose - the pointer highlights, the keyboard selects.
- **Double-click** - double-clicking a card opens its detail view.

## Command palette

`ctrl+k` opens a fuzzy-matched palette of every action the board can perform.
The palette and the help pane's key list are generated from one action registry,
and choosing a palette entry replays that action's key through the board's normal
handler - so the keymap, the help pane, and the palette cannot drift apart. A
test fails the build if they do. Matched characters are highlighted per grapheme
cluster, not per byte.

## Empty, loading, and error states

Every surface that could previously show a blank region now shows a designed one.

- **Empty** - an empty column reads `no cards` with the keybinding that fills it,
  rather than empty space.
- **Loading** - a board with no snapshot yet shows an animated loading state, and
  loading beats empty: a board that has not loaded never claims to be empty.
- **Errors** - failed operations render as a danger-tinted body row with a retry
  hint, above the action row, capped at three lines. A failed card move is
  distinguishable from a successful one for the first time since v1.0.1, when the
  status was recorded but never shown.
- **Busy** - the frozen busy strings (`adding comment...` and its siblings) are
  retired in favor of band states, so a busy panel reads the same way everywhere.
- **Settings** - the ready placeholder row is gone; the pane shows its real state.

## Help-line packing

Hint ladders are declared once and packed to the frame, instead of being built
twice for wide and narrow frames and then cut mid-word. Rungs are ordered by
importance: the pinned head and the rungs that get you out survive, the middle
drops from the end, and an ellipsis marks that something was dropped. The mark is
suppressed when no middle rung survives - a mark alone says less than the rung it
displaced, so at narrow widths the help pane shows `[Close] | ? or esc close
help` rather than `[Close] | …`.

## Dependencies

Two direct dependencies, both MIT, both pinned:

- `github.com/rivo/uniseg` v0.4.7 - grapheme cluster segmentation, so gradient
  ramps and match highlighting step by display cell rather than by byte.
- `github.com/sahilm/fuzzy` v0.1.3 - the command palette's matcher.

## Upgrade from v1.3.0

No database migration is required and nothing needs to be reconfigured. The
schema, the `kb serve` HTTP API, the MCP tool surface, the CLI flags, and the
storage keys are unchanged. Existing tasks, comments, links, tombstones,
settings, encrypted credentials, and import provenance remain in the same data
directory. Keep `kb.db`, `kb.db-wal`, `kb.db-shm`, and `secret` together when
backing up or moving a board.

Two visible behaviors change for anyone who has used the TUI since v1.0.1: a
footer notice now clears itself after five seconds, and a pressed control is
marked by reverse video instead of a `!` or `>` glyph. Neither is configurable
and neither affects scripted use.

Gradients and the launch mark need a truecolor terminal. On anything less they
degrade to flat hues automatically - no flag, no setting, and no missing
information.

## Install and verify

With Go 1.25.8 or newer:

```sh
go install github.com/RandomCodeSpace/kb@v1.4.0
kb version
```

The release contains five CGO-free binaries:

- Linux amd64 and arm64
- macOS amd64 and arm64
- Windows amd64

Download the matching binary and `SHA256SUMS` from the release, then verify it
before installation:

```sh
grep ' kb-linux-amd64$' SHA256SUMS | sha256sum -c -
```

Substitute the downloaded asset name. On macOS, pipe the matching manifest
line to `shasum -a 256 -c -`. On Windows, compare
`Get-FileHash -Algorithm SHA256` with the matching manifest line.

Every attached binary is built from the annotated v1.4.0 tag with `-trimpath`
and stripped debug data. Embedded Go metadata records the module, version,
source revision, target OS and architecture, and an unmodified source tree.
