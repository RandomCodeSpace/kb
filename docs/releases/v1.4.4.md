# kb v1.4.4

v1.4.4 is a patch release carrying four changes, all of them in the TUI. The
effort marker no longer overlaps its own letter and is now a colored square;
label pills lost their grey side bars, so an end cap carries the label's own
color everywhere; and a blocker reference in the card detail opens the card it
names. No command was added or removed, no flag changed, the schema, the
`kb serve` HTTP API, and the MCP tool surface are untouched, and no dependency
was added. Stored text is unchanged: this is rendering and navigation only.

## The effort marker is a colored square

The effort chip used to draw `◇` immediately followed by its letter. U+25C7 is
East Asian Ambiguous - it is counted as one cell and every width calculation kb
makes believes that - but plenty of terminal fonts draw the glyph wider than the
cell the cursor was advanced past, so `◇M` put the letter on top of the diamond.
Reported on v1.4.3 in both VS Code terminal and Windows Terminal, which is what
rules out a terminal-capability explanation.

Two changes land on that chip. First the rule: an ambiguous-width mark owns the
column after it. The next cell is a space, or the row ends. Then the marker
itself becomes a square keyed to the value:

```
P1 3d old ▐blocked▌ ▐in 2d▌ 🟦 S
P1 3d old ▐blocked▌ ▐in 2d▌ 🟨 M
P1 3d old ▐blocked▌ ▐in 2d▌ 🟧 L
```

Blue for `S`, yellow for `M`, orange for `L`. The letter stays beside the
square, for two reasons: color alone must not carry the value, and the letter is
what still reads on a font that has no pictograph and draws tofu.

The three squares are deliberately equal-width, so the chip changes value
without moving a column. An effort value outside the `S`/`M`/`L` scale - a
hand-edited board can carry `~XL`, since the markdown parser accepts whatever
follows `~` - still falls back to the diamond and renders exactly what it
rendered before. An empty value renders no chip at all, as before.

The chip is four cells with a square and three with the diamond fallback, in
both densities. The meta row measures each chip rather than assuming a width, so
the chip-drop order and the responsive column drop absorbed the extra cells with
no constant to chase. Every rendered row is still exactly the frame width at
every size checked, in both densities. The one visible cost is that the compact
flat row runs out one label earlier at the widths where that row was already
full.

## Two more marks got their column back

The same adjacency rule fixed two sites the report did not name, found by
auditing every non-ASCII glyph render site in the TUI with its width class
resolved from the Unicode tables rather than from memory:

- the top bar's shipped counter, `×1 shipped today` becomes
  `× 1 shipped today`;
- a column band whose label was long enough to truncate ended on `…` with the
  count starting in the very next column. The separator column is now reserved
  in every state, so no band's geometry depends on whether its label truncated.

Rails, pill caps and half-block letterforms are exempt and stay abutted. They
are not the same primitive: a separating column would not fix those glyphs, it
would delete them.

A guard test walks the rendered board at six sizes across both densities and
asserts the rule over kb's own glyph vocabulary, and the card detail overlay
gets its own walk. The vocabulary is resolved by reflection, so a mark added
later is picked up without editing the test.

## Pill end caps carry the label's color

A label pill is a colored word between two half-block end caps. The caps were
drawn in a neutral surface grey in several forms, which read as two grey bars
bracketing the label - near-invisible in truecolor and plainly visible once
quantized to 256 colors. In the indexed board golden the caps were index 234
against an index 233 ground: two adjacent greys.

Every end cap now carries the pill's own fill hue. That covers the inactive
filter pill, which withdraws the fill so it does not read as selected but keeps
its identity in the caps, and the scoped two-tone pill - every `project::` pill
on the board - which now reads hue-bracketed with the dark key half inside the
bracket. No cell count changed in any state or density; nothing but the cap
color moved.

Every call site was audited against the ground its pills actually land on -
card labels and meta chips, the filter bar, the card detail labels row - and no
ground mismatches existed. The seam on ordinary label pills was the scoped left
cap, which leads essentially every card's label row. That is now pinned by a
test rather than reasoned about, in five state and density combinations.

The 256-color separability audit is extended onto cap foregrounds: no color
slot quantizes onto the index of a ground it lands on, and no two slots collapse
onto one index as a cap color.

## Blocker references open the card they name

The card detail overlay drew its linked tasks as plain `#<seq>` text. The chips
identified a card but could not reach it, while a `kb://task/<seq>` reference
written in the same body already opened one. Every `#<seq>` chip the detail body
draws is now clickable - the `blocks` row, the `blocked by` row, and the
completion gate's reason clause - and reuses that same mechanism rather than
growing a second one.

A click opens that card's detail, taking the same path a click on the board card
takes. A card the current filter hides still opens. A sequence number no card on
the board carries is the same notice it has always been - `no card #N on this
board` - never an error and never a silent dismissal.

A blocker that no longer holds the card carries a mark inside its brackets, so
the row is readable without parsing status words:

```
blocks      [#21 doing]
blocked by  [#31 todo]  [✓ #32 done]  [☒ #33 cancelled]
completion gate  blocked: 1 open linked blocker [#31 todo]
```

Done blockers take a tick, cancelled ones take the crossed box that already
means "dropped rather than completed" in kb's vocabulary - the completion gate
has always treated the two identically, so the row does too. Open blockers take
no mark: the mark is the exception the eye is looking for, and marking every
chip would make the row uniform again.

Hovering a chip raises its own ground a single tier, scoped to the chip's cells.
The chip is bracketed text rather than a filled pill, so it has the tier step to
spend. Both treatments cost zero cells. Hit regions are recorded by the rows
that draw the chips, ride the detail body's scroll viewport, and clip at the
window edge; a chip the row truncated away registers nothing, and a chip keeps
its identity across the frame that scrolled it.

## Pointer only, deliberately

Activation is by pointer, as it is for the inline `kb://task/<seq>` references
of v1.4.3. The idle detail overlay has no focus traversal to hang an activation
off: `tab` is bound inside the add-link action pane alone, and the body has no
row cursor. Wiring a key here would mean inventing a mode for one row rather
than using the existing interaction model, so it is not in this release. The
chips are already controls with stable ids, so they fall into row focus for free
if the overlay ever grows it.

## Upgrade from v1.4.3

No database migration is required and nothing needs to be reconfigured.
Existing tasks, comments, links, tombstones, settings, encrypted credentials,
and import provenance remain in the same data directory. Keep `kb.db`,
`kb.db-wal`, `kb.db-shm`, and `secret` together when backing up or moving a
board.

Nothing changes for scripted use. The wire format, the stored text, and every
export are identical to v1.4.3. An effort value is stored as the characters the
author typed and always was; the square is drawn from it, never stored. The only
visible differences are in the TUI.

A terminal whose font carries no pictograph draws the effort square as tofu. The
letter beside it is what keeps the chip readable in that case, and it is the
same font risk kb already accepts for its block-drawing glyphs.

## Install and verify

With Go 1.25.8 or newer:

```sh
go install github.com/RandomCodeSpace/kb@v1.4.4
kb version
```

The release contains five CGO-free binaries:

- Linux amd64 and arm64
- macOS amd64 and arm64
- Windows amd64

Download the matching binary and `SHA256SUMS` from the release, then verify it
before installation:

```sh
grep ' kb-linux-amd64$' SHA256SUMS | sha256sum -c -
```

Substitute the downloaded asset name. On macOS, pipe the matching manifest
line to `shasum -a 256 -c -`. On Windows, compare
`Get-FileHash -Algorithm SHA256` with the matching manifest line.

Every attached binary is built from the annotated v1.4.4 tag with `-trimpath`
and stripped debug data. Embedded Go metadata records the module, version,
source revision, target OS and architecture, and an unmodified source tree.
