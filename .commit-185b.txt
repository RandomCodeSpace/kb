feat(tui): run the mouse-mode machine on the command palette

PR #195 shipped the palette keyboard-only and left the pointer wiring to
this slice: it installed no handler and cleared the board's, so a click
while it was open landed on nothing.

The palette's result list is an overlay choice surface, which is exactly
the scope ratified call 9 gives the machine, so it is the first surface to
run all of spec section 10.5.2 rather than only the affordance half.

- cmdpalette.MouseHandler builds the frame's map from the same windowed row
  slice the body draws, so a hit region can never address a row the panel
  did not render. Every region is derived from the row that drew it, never
  from matching rendered text. The panel's surround is the palette's own
  backdrop and dismisses; nothing is lost by that, because opening the
  palette is always a fresh search.
- Rows carry a stable control id keyed by entry index, so one string is both
  the click target and the row the machine reads back out.
- The hovered row is the acting selection: it renders the focus gutter and
  the bold label, the keyboard cursor renders nothing, and the scroll hint
  follows it, so exactly one row is marked at any moment. Hover raises that
  row's fill to OverlayBand on top of it, panel edge to panel edge, at equal
  cell width and identical stripped text.
- Keys apply rows 7 and 8: up, down, ctrl+p and ctrl+n adopt the hovered
  anchor and then move from it; every other key runs unadopted against the
  keyboard cursor. Both turn mouse mode off.
- A generation counter retires the map on every refilter, so a release
  resolved against a frame the query has since changed runs nothing rather
  than whatever action slid into that row's place.
- The scroll window still follows the keyboard cursor only: the pointer is
  inside the drawn window by construction, and a hover that moved the window
  would drag the list out from under the hand holding the mouse.

widget.OverlayRowOn generalizes OverlayRow onto a named surface, which is
what lets a choice row's own padding carry the raised fill; a row that is
not activatable is not hoverable and keeps OverlayRow. The palette's query
field is one of those.

cmdpalette.IsMessage now claims pointer feedback and the palette's own
activations rather than key presses: keys stay with the caller's open-overlay
branch, which owns the interrupt ladder.
